# 入口網站點擊統計

## 啟用（一次）

在入口網站目前使用的 Supabase 專案，開啟 SQL Editor，執行：

`supabase/migrations/20261012160000_portal_usage_analytics.sql`

此檔案以交易建立獨立的 `portal_tool_clicks` 資料表與兩個函式，可重複執行，不會清除點擊資料。不修改 `tool_statuses`、原開關權限、登入設定或帳號。GitHub Pages 部署不會自動執行資料庫 migration。

完成後，登入入口網站並啟動一個應用程式。管理員登入後台 → 使用統計 → 重新整理，確認本月增加一次。一般入口帳號不應能呼叫統計讀取函式。

若尚未安裝，後台顯示「點擊統計尚未啟用」，而非假裝點擊數是零。安裝前的點擊不會補算。

## 計數定義

- 每次按下可使用卡片的啟動按鈕計一次，包括外部新分頁。
- 重複點擊算多次；不是獨立訪客、使用時長或成功載入次數。
- 關閉／尚未開放卡片、直接網址、`?tool=` 自動開啟、iframe 重新整理與浮動 Agent 連結不計入。
- 使用伺服器收到事件的時間，以 Asia/Taipei 分月，不信任用戶端時鐘。
- 僅記錄事件 UUID、工具 ID、時間，不存個人身分、IP 或瀏覽器資訊。
- 事件 UUID 防止同一事件重送造成重複記錄；刻意重複點擊仍會計入。
- 使用登入中的入口帳號送出，不等待紀錄完成再開啟工具。網路失敗不重送、可能漏計；此功能適合使用趨勢觀察，不是稽核或計費紀錄。

## 安全與隔離

- 入口帳號只能透過 `record_portal_tool_click` 新增受允許工具的事件；無直接資料表讀寫權限。
- `get_portal_tool_clicks` 在資料庫驗證 `app_metadata.role = admin`，一般帳號無法讀取統計。
- 年度統計在資料庫彙整，最多 12 個月 × 12 個工具，不受事件筆數超過 API 預設 1000 筆限制。
- 新增工具時，需在 SQL 的工具 ID 限制中增加 ID。
- 一般帳號仍可能刻意重複呼叫紀錄函式，因此點擊數不能當作真實人數或防弊證據。
