# 離線 Programmer 操作選單設計規格

## 目標

在未連接 Programmer／Writer 時，讓使用者可於現有 Web Terminal 內以「離線模擬」方式操作 LP56 Programmer 選單。離線操作只模擬選單導覽與參數輸入，不執行硬體命令，也不產生假造的硬體量測結果。

## 範圍

- 修改：`tool\web_terminal\index.html`
- 參考：`function_tree.md`、`LP_ICIDCheck.c`
- 保留既有 Web Serial、LOG 錄製、流程錄製／回放、終端機清除、凍結比對與字體縮放功能。
- 收錄 `function_tree.md` 中有明確說明的主選單與子選單。
- 隱藏「未標註說明」、重複且無法判定語意的項目，避免離線介面提供不完整或誤導性的操作。
- 不新增套件、不建立獨立 React 專案、不連接 API 或後端。

## 使用者流程

1. 使用者在未連線狀態開啟「離線模擬」切換。
2. 左側 LIVE 終端機顯示離線狀態與 `mh_spi_menu` 主選單。
3. 輸入主選單按鍵後進入對應子選單；有參數的項目顯示提示並接受文字輸入。
4. 按 `Enter` 確認輸入，顯示「已接收參數、離線不執行硬體」的模擬 Log。
5. `q` 或 `ESC` 返回上一層；主選單中則返回離線初始畫面。
6. 無效按鍵顯示錯誤並停留在目前選單。
7. 關閉離線模式後，鍵盤輸入恢復既有即時終端機行為。

## 架構

採用單檔、最小改動方案：

- 在現有控制列加入離線模式切換與狀態提示。
- 以 JavaScript 資料物件保存選單樹；節點包含按鍵、顯示名稱、子項目與參數提示。
- 以小型狀態機保存目前選單節點、輸入階段與返回位置。
- 離線輸出沿用既有 `writeToTerminal()`，確保 Big5 顯示、捲動、清除與凍結比對行為一致。
- 即時模式仍由既有 `sendSerialData()` 與 Web Serial 連線流程處理。
- 離線模式的輸入分流必須先於即時傳輸，且不得呼叫 `navigator.serial`。

## 模擬輸出與錯誤處理

離線輸出只允許描述：

- 目前模式與選單位置。
- 使用者選取的項目。
- 使用者輸入的參數。
- 明確的「離線模擬，未執行硬體」訊息。

不得輸出虛構的 SPI ID、Vt、Program、Erase、Checksum、電流或其他硬體測量／成功結果。輸入錯誤、無效按鍵與不完整參數需直接顯示在終端機，不能靜默忽略或成功形狀降級。

若使用者在離線模式開啟時嘗試連接 Writer，介面需提示先關閉離線模式；避免同一輸入同時被本機狀態機與串口處理。

## 驗證

- 瀏覽器 smoke test：未連線即可啟用離線模式。
- 逐層驗證所有收錄的主／子選單、返回操作、參數輸入與無效按鍵。
- 確認離線操作不要求權限、不開啟 Web Serial、不寫入串口。
- 確認切回即時模式後，既有連線、輸入、錄製、回放、LOG、凍結比對與字體縮放功能仍可使用。
- 執行可用的 HTML／JavaScript 語法檢查。

## 明確不包含

- 真實 Programmer 命令執行。
- 假造硬體回傳值或測試結果。
- 離線錯誤／延遲注入器。
- 離線操作 JSON 匯出。
- 新增後端、API、套件或獨立前端建置流程。
