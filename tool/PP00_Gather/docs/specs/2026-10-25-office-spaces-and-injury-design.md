## 一、 設計背景與核心目標

目前 PP00 Gather 虛擬辦公室頂部區域（y: 70 ~ 440）配置了 1 間 VP 大老闆室、1 間 PP00 處長室，以及連續 5 間空置的主管會議室（`PP10` ~ `PP50`，見 `static/js/world.js` 中的 `directorBlocks`）。這些房間缺乏專屬 NPC 與獨特互動，形成了大面積的公設比浪費。同時，現有經驗值系統存在「每級固定 100 EXP 純線性」、「滿級僅 1,900 EXP 極易封頂」、「受罰無成本」、「清快取等級蒸發」等重大缺陷。

本整合計畫達成四大核心升級：
1. **空間重構與物資消耗閉環**：將 `PP10` 至 `PP50` 改造成 5 大特色機能空間。為避免「消費經驗導致自願降級」的經典矛盾，扭蛋與修裝**全面改採地上撿拾的零食與雜物道具（`category === 'weapon'`）進行回收兌換**，讓 EXP 專注於等級與懲罰。
2. **傷害分級機制（解決邏輯死角）**：新增「一級：輕微挫傷」，打破現有「致命重傷強制在會議室躺平 5 分鐘完全定身」的二分法，使「受傷走去電競室療傷」具備完全成立的代碼邏輯。
3. **硬核非線性經驗值與動態降等**：
   - 升級為 **Season 2**，以雲端為最高真實權威，全體同仁首次登入自動無痛歸零重啟。
   - 採用 **Lv.1 ~ Lv.20 漸進式非線性階梯**，滿級門檻上修至 **20,000 EXP**（滿級後經驗可繼續累積作為名人堂榮譽分數）。
   - 實裝 **「損失大於收益（Loss > Gain）」** 懲罰原則：被長官關門痛扁 (-50 EXP)、致命重傷 (-80 EXP)、大逃殺滅團 (-120 EXP)。
   - 實施 **「嚴格動態降等（Strict Dynamic De-Leveling）」**：經驗跌破門檻立即掉級、稱號與被動數值即刻縮水！
4. **工業級分散式架構與資安強化**：
   - 聖殿護盾納入房長（RoomMaster）權威仲裁，杜絕多人同步幽靈掉寶。
   - RMA 客訴任務實裝全域互斥鎖（Mutex），防止多人重複領取經驗。
   - 複合主鍵 `(user_name, unit)` 防止同名碰撞；PIN 碼全面採用 SHA-256 雜湊儲存，實裝防暴力破解鎖定。
   - 熱重載（`btnGameReload`）改為可靠 `await` 同步，並設置每日簽到（Daily Login Cap）防刷經驗機制。

## 二、 負面狀態與傷害分級機制（Injury Tier System）

現行系統僅有 `isInjured = true`，一旦觸發便將角色固定在事發現場或會議室 B 躺平 5 分鐘（`sleep_bed`），移動事件直接 `return`，完全無法自主行動。為使電競 Lounge 舒壓功能成立，正式建立二級分級制度：

```
[受擊判定]
   ├── 5% 致命重傷  ──> 二級：致命重傷（會議室 B 躺平 120~300 秒，完全定身，需等待或他人急救）
   └── 15% 普通挫傷 ──> 一級：輕微挫傷（頭頂冒 🩹，移速 -30%，可自由走動至電競室自癒）
```

### 1. 一級：輕微挫傷（Light Injury / 扭傷）
- **觸發條件**：遭受怪物揮擊、保全攻擊或同事一般擊飛時，有 **15% 機率** 觸發。
- **狀態表現**：
  - 角色頭頂浮現創可貼表情符號（`🩹`，持續至痊癒）。
  - 移動速度降低 **30%**（模擬扭傷一拐一拐的步伐）。
  - **保有完整行動能力**：可自由走動、拾取物品、使用設備與對話。
- **治癒途徑**：
  1. 自行走進「電競娛樂 Lounge」入座打電動 5 秒，立即治癒。
  2. 由其他同仁按 `[E]` 進行簡易急救包紮（耗時 2 秒）。
  3. 持續 60 秒後自然緩解痊癒。

### 2. 二級：致命重傷（Critical Injury / 會議室休養）
- **觸發條件**：遭受同事 5% 致命重擊、特定 Boss 終結技或鳥人逮捕。
- **狀態表現**：
  - 維持現有機制：強制轉移或鎖定至會議室 B。
  - 動作固定為 `sleep_bed`，全身定身無法走動。
  - **休養時間公式**：`Math.max(120000, 300000 - (lv - 1) * 6000)` 毫秒（2 ~ 5 分鐘，隨等級縮短）。
  - **排位防重疊機制**：嚴格沿用 `static/js/combat.js:102` 之網格巡檢演算法（y: 1350..1750, x: 740..1130），自動尋找空位落點，絕不發生多人重疊躺在同張病床上的視覺 Bug。
- **治癒途徑**：
  1. 靜待休養時間結束。
  2. 由健康同仁靠近按住 `[E]` 進行急救拉起。

## 三、 五大全新機能空間詳細規格與互動機制

頂部原 `directorBlocks`（PP10 ~ PP50）依序替換為下列 5 間獨立機能空間：

```
+-------------------------------------------------------------------------------------------------------+
|  VP室  | PP00處長室 | 1. RMA救火指揮所 | 2. 電競娛樂Lounge | 3. 裝備修復工具台 | 4. 綠乖乖聖殿 | 5. 盲盒扭蛋福利社 | 茶水間 |
+-------------------------------------------------------------------------------------------------------+
```

### 空間 1：客戶 RMA 救火指揮所（RMA War Room）
- **原空間**：`PP10 主管會議室`（x: 886 ~ 1110, y: 70 ~ 440）
- **視覺佈置**：紅色警報燈、白板 Issue 追蹤圖、堆滿報告的長桌、中央紅色緊急熱線電話。
- **核心互動機制**：
  1. **接聽客訴**：電話響鈴光芒；同仁靠近按 `[E]`「接聽緊急客訴」。
  2. **全場互斥鎖（Mutex）防止競態**：
     - 首位按 E 接案的同仁向全場廣播 `rma_claim { claimer: localPlayer.name, targetId: 'ws_x' }`。
     - 全場設備同步標記「該機台由【XXX】搶修中」，其他同仁走近電話僅會看到「搶修中提示」，**嚴禁多人同時重複派工**。
  3. **手持報告搶修**：接案同仁獲得 1 張現成道具 `rma_report`（客訴報告），前往紅字警報機台執行 3 秒 Debug。
  4. **唯一獎勵結算**：僅有接案人可發起修復結算，修復後全場廣播警報解除，獲得 **60 EXP**（不呼叫 `forceLevelUp`，防止等級跳級通膨）。

## 五、 後端資料庫持久化：免 Email 認證之地端與雲端混合架構

### 1. 現行後端資料庫診斷
目前後端資料庫（Supabase）僅開立 3 張資料表，定位為「即時在線路由器與資安稽核」，無長期進度存檔：
- `gather_online_users`：暫態在線表，斷線 35 秒即被 `DELETE`。
- `gather_audit_logs`：純流水帳稽核。
- `gather_game_config`：全域設定（唯讀）。

### 2. 混合運作機制（方案一：無痛姓名認證 ＋ 4 位數 PIN 碼）
- **同仁體驗完全不變**：同仁打開網頁，依然只輸入「英文名 / 綽號（如 `Tony`）」＋「部門（如 `PP32`）」，點擊進入。
- **首次登入（建檔與設防）**：
  - 系統彈出極簡輸入框：「請設定您的 4 位數通關 PIN 碼（如 1234，換電腦登入防冒用）」。
  - 地端將 PIN 碼以 SHA-256 計算為雜湊 `pin_hash` 後上傳後端建立檔案。
- **後續登入（原電腦免驗證）**：
  - 本地快取自動驗證成功，直接秒進辦公室，不需重複輸入 PIN 碼。
- **換電腦登入（跨裝置無縫繼承）**：
  - 在新電腦輸入同名同部門時，系統提示輸入 4 位數 PIN 碼。驗證通過後拉回雲端進度。
  - **防暴力破解保護**：連續輸錯 5 次 PIN 碼，鎖定該帳號 15 分鐘。

### 3. 「重新整理畫面（btnGameReload）」與每日簽到防刷
1. **可靠同步**：取消脆弱的定時器，改為在跳轉前執行 `await syncUserProfileToBackend()`，確認後端收妥回執後才調用 `window.location.reload()`。
2. **每日簽到防刷機制（Daily Login Cap）**：
   - 後端記錄 `last_login_date`（例如 `2026-10-26`）。
   - 僅當天**首次登入給予 +50 EXP 簽到獎勵**；重新整理（`isAutoReload = true`）或當天重複關閉開啟分頁，一律不再重複給予 +50 EXP！

### 4. 後端資料表完整規格（`gather_user_profiles`）
```sql
create table if not exists gather_user_profiles (
  user_name text not null,                    -- 使用者名稱 (小寫英文，如 'tony')
  unit text not null,                         -- 部門單位 (如 'PP32')
  display_name text not null,                 -- 顯示暱稱 (保留大小寫，如 'Tony')
  pin_hash text not null,                     -- SHA-256 雜湊處理之 PIN 碼 (絕不存明文)
  pin_failures integer default 0,             -- PIN 輸錯累計次數
  locked_until timestamp with time zone,      -- 防暴破鎖定結束時間
  exp integer default 0,                      -- 核心：累積經驗值
  level integer default 1,                    -- 核心：當前等級 (1 ~ 20)
  season integer default 2,                   -- 賽季標記 (第二賽季 Season 2)
  stored_outfits jsonb default '[]'::jsonb,   -- 珍貴外觀清單: [{"id":"...","durability":5,"is_worn":true}]
  avatar_id text default 'office_1',          -- 預設上班族頭像 (office_1 資深工程師)
  total_logins integer default 1,             -- 累計登入次數
  last_login_date date default current_date,  -- 每日簽到日期標記
  last_login_at timestamp with time zone default now(),
  updated_at timestamp with time zone default now(),
  primary key (user_name, unit)               -- 複合主鍵，杜絕跨部門同名衝突！
);
```

### 5. 地端（LocalStorage）vs 後端（Supabase）資料分工邊界

| 分工層級 | 負責儲存之具體項目 | 儲存理由與特性 |
| :--- | :--- | :--- |
| **後端資料庫 (Supabase)**<br>*永久保存・跨裝置同步* | 1. **帳號核心**：`user_name` + `unit` 複合主鍵、`pin_hash`<br>2. **長期心血**：`exp`、`level`、`season`<br>3. **珍貴資產**：`stored_outfits`（含精確耐久與穿著狀態）<br>4. **統計與簽到**：`total_logins`、`last_login_date` | 換電腦、清快取皆不遺失。<br>具備防作弊公信力，不再能被 F12 隨意修改經驗值。 |
| **地端快取 (LocalStorage)**<br>*即時運算・暫態數據* | 1. **隨身雜物**：3 格手持武器與當前剩餘耐久度<br>2. **負面計時**：輕微挫傷 🩹 60 秒倒數<br>3. **本機設定**：音量、縮放鏡頭偏好<br>4. **離線快取**：斷線時之降級防禦快取 | 武器揮 3 次就壞、零食隨吃隨掉，屬於暫態雜物，不上雲端減輕伺服器負擔。 |
| **即時線上表 (Online Users)**<br>*瞬態廣播・離線即刪* | 1. **即時座標**：`x`, `y`, `dir`<br>2. **動作姿勢**：`action_state`（打 Code、躺平、拜拜）<br>3. **心跳偵測**：`last_heartbeat`（每 8 秒發送，離線 35 秒自動 DELETE） | 純粹用於讓螢幕上看得到其他同仁即時走動，不影響個人存檔。 |
