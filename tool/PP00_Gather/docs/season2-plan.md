> 給執行代理：依下列階段逐項實作，使用 executing-plans 工作流程。先讀本文件、最新 main 與 AGENTS.md，再建立獨立分支。未核實的函式名稱、資料表與座標不能當成現況保證。不要直接執行舊稿 SQL。每階段先建立會失敗的行為測試，再實作、驗證與提交；不得以模擬測試取代最後的實際多人驗證。

**目標**：保留五個新房間與使用者已確認的硬核經驗、降級制度，同時避免重複結算、誤刪資產、多人不同步及不安全的 PIN 登入。

**架構**：前端負責操作與動畫；房長負責短期場景協調；後端負責帳號、時間、資產交易與經驗帳本。房長仍是玩家瀏覽器，不能單靠房長宣稱具備完整防作弊能力。

**技術方向**：既有 Canvas / JavaScript、Supabase Postgres 與 Edge Functions；新增套件只在確有需要時引入並固定版本。先核對現有 Supabase 設定與官方文件，不修改入口網站應用程式開關。

## 1. 必須保留的規則與本版取捨

### 1.1 已由使用者確認

- 採硬核經驗：受罰扣 EXP，可降級，最低 0 EXP / Lv.1。
- 等級最高 20；Lv.20 門檻 20,000 EXP，之後可繼續累積。
- 掃地阿姨、VP、PP00 處長遭玩家攻擊時，各有 50% 機率觸發抓人。
- VP / 處長帶到各自辦公室；阿姨帶到廁所。抓人後 8 秒連續毆打，整次扣 50 EXP。
- 這 8 秒是特殊動畫，不增加一般傷害、鳥人命中數，不觸發重傷、掉物、服裝損毀或擊暈；不按每次動畫揮拳重複扣點。
- 重傷送會議室 B，位置不能重疊。
- 十位上班族基礎人物；特殊服裝獨立裝備，不改玩家身分。CRT、牛頭、晶圓盒、珍奶是遮臉頭套，保留原身型衣服。
- 背包總計 10 件、服裝最多 3 套；穿著中仍計入。
- NPC 擊倒後 30% 物品掉落、服裝額外 5% 掉落；僅打中一次不算擊倒。
- 一般有效 NPC 受擊保留 20% 玩家掉物、20% 擊暈、40% 穿著服裝損耗判定；服裝 5 點耐久歸零銷毀。
- 一般通知右上最多 5 則，每則 3 秒；重傷狀態置中透明文字，不能遮手機頂部按鈕。底部互動列位置保留。
- 這是隱藏 app，不在 repo 根目錄 README 或入口卡片公開介紹。

### 1.2 本修訂建議採用的明確規則

以下為消除歧義所採用的設計選擇，須隨本文件一起審閱：

- 一般攻擊重傷 / 輕傷採一次互斥抽籤，機率為 5% / 15% / 80% 無新傷；鳥人活動攻擊另依三擊制。
- 不新增未定義的 Boss 終結技。將來新增時另列規則。
- 服裝與可兌換的武器材料統一存雲端；取代 v2.1「武器僅存本機」方案。
- 每個帳號同時只允許一個可操作的遊戲連線；新裝置接手後，舊裝置停止操作與保存。
- 首次 Season 2 重置登入為 0 EXP，當天不另送 50；下一個台灣日期起可領每日首次登入 50。
- 原有本機物品一次性遷移，標記來源為 legacy；保留既有物品，但不能聲稱這批歷史資料經過防作弊驗證。
- 合作主動技能不列入本版必要範圍；咖啡指既有道具加速，未實作的技能不得被寫成已有功能。

## 2. 傷害事件、抓人與負面狀態

### 2.1 每次事件只結算一次

每次攻擊具備 event_id、攻擊者、目標、來源類型、房間世代與伺服器接受時間。重送同一 event_id 不重抽機率、不重複扣點、不重複掉物。動畫事件與傷害事件分開。

處理順序：
1. 驗證目前連線、目標、距離、攻擊冷卻與事件是否已結算。
2. 處理有效護盾；若吸收，本次不進入後續傷害與鳥人計數。
3. 特殊抓人事件走獨立流程；一般攻擊不在抓人動畫中繼續命中該玩家。
4. 鳥人活動攻擊依活動規則；其他一般攻擊依傷害分級。
5. 針對允許的來源獨立判定掉物、擊暈、服裝損耗，最後發布一次結果。

一般 NPC 攻擊可同時造成輕傷與擊暈；若已重傷，不另外播放擊暈，但符合條件的掉物 / 服裝損耗仍最多一次。PvP 不新增服裝損耗；其既有掉物 / 擊暈行為實作前先核對，不能擅自擴大。

### 2.2 一般傷害

- 一次抽籤：0 ≤ r < 0.05 重傷；0.05 ≤ r < 0.20 輕傷；其餘不新增傷勢。
- 輕傷：60 秒，自由行動，移速乘 0.7；再次輕傷更新至本次受擊後 60 秒，不疊加多層減速。
- 輕傷急救固定 2 秒；電競室連續互動 5 秒可治癒。
- 重傷：一次扣 80 EXP；送會議室 B，鎖定移動，使用 sleep_bed。
- 已重傷或正在特殊抓人動畫時，不再接受新的一般攻擊判定。

### 2.3 鳥人追殺

- 保留每天每 15 分鐘一場、每場 60 秒。
- 活動中的鳥人攻擊不抽 5% 一般重傷；第 1、2 次有效命中只更新活動命中數，第 3 次重傷退場。
- 第 3 次只扣 120 EXP，不疊加 80 EXP。
- 活動外鳥人攻擊依一般攻擊；單純被鳥人帶去房間不等於重傷。
- 每場每人只結算一次退場懲罰；結束後清除本場命中數。

### 2.4 抓人動畫

- 針對有效玩家攻擊事件抽一次 50%；抓人反擊與 NPC 本次受擊動畫皆需可見。
- 只有仍存活、未被擊倒、未忙於其他抓人事件的 NPC 可啟動；同一次攻擊的 NPC 擊倒優先，不再抓人。
- NPC 與玩家移往對應可站立落點，鎖定 8 秒；同 NPC 一次抓一人，其他攻擊不得反覆刷新倒數。
- 整次扣 50 EXP，死亡 / 重傷系統不參與。倒數結束解除鎖定與門閘，NPC 回正常路徑。
- NPC 或玩家斷線、房長切換、背景停留後回來，依後端截止時間恢復或結束；不得永久關門。

### 2.5 休養與急救

- 重傷時間依扣點後等級一次計算：max(120000, 300000 - (lv - 1) * 6000) 毫秒。
- 此公式在 Lv.1～20 實際為 300～186 秒；120 秒只是保底，不宣稱 20 級能達到 120 秒。
- 急救重傷耗時依施救者開始時等級固定：max(2000, 5000 - (lv - 1) * 150) 毫秒，20 級 2150ms。
- 施救者須健康且維持距離；移動離開、受擊、登出取消。多人同救只讓第一個完成者結算。
- 救人獎勵 50 EXP，每個重傷事件只能領一次；輕傷包紮不給此 50 EXP。
- 會議室 B 以後端分配席位，檢查牆壁家具與既有席位。席位不足擴至同室預先驗證的備援格，不隨機疊人。
- injured_until 與抓人 locked_until 保存後端，離線倒數繼續，不能刷新逃避。

## 3. 等級、獎勵與移速

### 3.1 累計門檻

```js
const LEVEL_EXP_REQUIREMENTS = [
  0, 100, 250, 450, 700, 1020, 1420, 1920, 2540, 3300,
  4200, 5200, 6300, 7500, 8800, 10500, 12500, 14800, 17300, 20000
];
```

等級為不超過經驗的最高門檻索引 + 1。EXP 使用足夠容量的整數，後端約束非負；等級從 EXP 衍生，不接受前端另行指定 level。

稱號保留 v2.1：Lv.1～5 菜逼八工程師；6～10 高級打雜師；11～15 資深地下處長；16～19 專業老司機；20 PP00之神。

### 3.2 結算

- 撿取合資格世界生成物品 +15；NPC 擊倒 +30；重傷急救 +50；每日簽到 +50；RMA +60。
- 每個掉落 ID 只能產生一次拾取獎勵。玩家自行丟棄、交換、扭蛋產物、系統退回物品不給拾取 EXP，防止丟撿刷分。
- 同一 NPC 生命週期只給一次擊倒獎勵；重生後建立新生命週期 ID。
- 取消一般設備修復的 forceLevelUp 跳級；一般非 RMA 修復每次有效故障最多 +30，RMA 目標只給任務 +60，不雙領。
- 懲罰：抓人 -50、一般重傷 -80、鳥人三擊 -120；這三種事件各自排他結算。
- 明列為固定值的 RMA / 簽到 / 懲罰 / 遷移不受裝備經驗加成；其他獎勵若沿用裝備加成，由後端依實際裝備計算，不能信任前端加成百分比。
- 降級一次重算所有被動；已開始的急救 / 休養不反覆延長，下一次事件才使用新等級。
- 超過 20,000 的 EXP 仍會被懲罰扣除，跌破 20,000 才降至 19 級。榜單顯示目前累計值，不另建立不可扣的榮譽資產。

### 3.3 被動與移速

- 等級移速：每級 +2%，20 級 +38%。
- 武器揮擊免耗：每級 +1 個百分點，20 級 19%；不適用服裝受擊損耗。
- 拾取半徑：30 + (lv - 1) px，20 級 49px；僅增加合法拾取距離，不隔牆吸取。
- 加速同類不疊層，刷新期限；不同來源採加總百分比：baseSpeed × (1 + 等級加成 + 電競加成 + 已有道具加成)，再乘輕傷 0.7，最後限制 totalSpeed ≤ 8.0（沿用現有單位）。
- 定身優先，最終移動為 0。降級、換裝、Buff 到期均由同一計算入口更新，避免互相覆寫。
- 上限不是穿牆保證；碰撞使用分段移動，最大步長不超過碰撞安全步長，掉幀時也不能一步跨牆。

## 4. 五個機能空間

沿用原稿 PP10～PP50 的房間順序與配色主題；位置實作前以最新地圖核對，不硬套舊行號。保留 VP、PP00、茶水間與會議室 A/B。每間家具留出可進出通道，測試手機全景與一般鏡頭。

### 4.1 PP10：RMA 救火指揮所

紅色警報燈、問題白板、報告長桌與紅電話。全房間同時一個任務。

- 後端產生 task_id 與可達設備目標；電話接案是後端條件更新 idle → claimed，不靠先廣播者獲勝。
- 任務以 player_id 識別，不以可重名的顯示姓名。
- 客訴報告為任務附件，不佔背包、不當武器、不當扭蛋材料；畫面可顯示手持報告特效。
- 靠近目標連續操作 3 秒完成；後端檢查接案者、任務狀態與時間，一筆交易完成任務及 +60。
- 任務最長 120 秒；離線超過 35 秒取消並清理任務故障，其他人可重新接案。
- 系統生成的任務故障不覆蓋原有真實故障；目標不可用時換目標或退回 idle，不發獎。
- 新加入玩家先取快照；任務完成廣播只發一次。完成後冷卻 30 秒再響鈴。

### 4.2 PP20：電競娛樂 Lounge

墨藍地毯、RGB、雙人沙發、電視、兩台街機。

- 按 E 入座，play_arcade；移動鍵取消，不累積零碎互動時間。
- 連續 5 秒治癒輕傷，獲得 30 秒 +15% 移速及一次擊暈免疫。
- 個人領取冷卻 60 秒；免疫只持續 30 秒，最多一層，不抵消傷害 / 掉物 / 服裝損耗。
- 重傷者不能自行走來或以選單遠端觸發。

### 4.3 PP30：裝備修復工具台

金屬工作台、工具牆、回收箱。

- 選一件未滿耐久的武器為修復目標，再選另一件未裝備的 category=weapon 作材料。
- 禁止服裝、任務附件、鎖定交易中的物品與目標本身作材料。
- 3 秒操作完成後，由後端同筆交易消耗材料並修滿目標；中斷不消耗。
- 目標已銷毀、材料不存在、版本不符、目標已滿耐久時拒絕，不扣物。
- 本版不提供服裝工具台修復，服裝透過重複扭蛋修復。

### 4.4 PP40：綠乖乖聖殿

金綠神龕、乖乖、參拜墊。參拜 3 秒後後端核發一次性護盾，持續 180 秒，個人冷卻 180 秒。

- 擋下一次一般 NPC / PvP 傷害，或鳥人活動有效攻擊，吸收該次全部衍生效果與命中數。
- 不擋幽靈單獨嚇睡與玩家主動攻擊長官引起的特殊抓人，不當成通用免罰券。
- 後端原子消耗護盾，兩個同時命中最多擋一次；以 shield_absorbed 結果廣播，不偽裝成普通閃避。
- 房長持有快照供動畫，但不能自行核發護盾。新房長 / 重連從後端恢復期限與已消耗狀態。

### 4.5 PP50：盲盒扭蛋福利社

黃粉扭蛋機、服裝櫥窗；抽取既有 COSTUME_CATALOG，不虛構未畫好的新服裝。

- 玩家明確選兩件未裝備 weapon；後端驗證不同 item_instance_id、所有權與可交易狀態。
- 每個 request_id 只抽一次。後端隨機挑一款既有服裝，本版各款等機率，不宣稱有未定義的稀有度。
- 有同款時優先修復其中耐久最低的一件至 5；同款全滿耐久則退回材料，結果仍記錄已完成，重送不能重抽。
- 無同款且未滿三套時產生 5/5 新服裝；仍需驗證交易後總背包 ≤10。
- 滿三套且抽到新款，產生 pending 選擇：材料先保留但不可另用，玩家選一件服裝以舊換新或取消。
- 確認時同筆交易扣兩件材料、銷毀所選舊服裝、加入新服裝；穿著中的舊服裝被換掉時自動卸下並廣播外觀。
- 取消或 60 秒未確認：保留原物品、釋放材料，不扣 EXP，不產生可再次領取的獎品。換掉的舊服裝銷毀，不生成可重撿地上物。
- 重連仍看到相同 pending 結果；斷線不能免費保留新服裝，也不能重抽既有 request_id。

## 5. 帳號、資產與同步：可行的安全邊界

### 5.1 姓名、部門與 PIN

保留免 Email 體驗；姓名＋部門是登入索引，不是身分驗證憑證。

- 後端使用永久 player_id；對正規化 (name_key, unit) 設唯一約束。去除首尾空白、姓名大小寫不敏感、部門使用白名單。
- 為保留 v2.1 體驗，本版仍允許四位數 PIN，但僅定位為小型同事遊戲的簡易驗證，不能宣稱企業級安全。介面不以 1234 作建議。
- PIN 經 HTTPS 送後端，使用成熟的 Argon2id 密碼雜湊實作、隨機 salt；若部署環境不支援，選官方支援的等效專用密碼雜湊方案，禁止退回單次 SHA-256。
- hash 不提供前端讀取，也不把 hash 本身當免密通行證。密鑰只在後端。
- 登入成功發不可預測的隨機 session token，後端只存 token hash，設定到期與撤銷；每次資產操作均驗證。瀏覽器記住 token 有被惡意腳本竊取的風險，應禁止不可信腳本與 HTML 注入。
- 帳號五次錯誤鎖 15 分鐘，後端另限制來源請求頻率；失敗計數不可由客戶端重設。錯誤訊息不公開帳號是否存在。
- 登出撤銷本次 session；「登出/返回入口網站」綁定相同行為。忘記 PIN 由管理者查核身分後重設並撤銷全部 session，不以同名直接覆蓋。
- 同名帳號首次註冊仍可能被先佔用；本版接受管理者處理，若要防止需另做邀請碼，不假稱 PIN 已解決首次身分查核。

### 5.2 後端資料模型（邏輯規格，不是可直接部署 SQL）

以下表名為新增提案，先核對既有 schema，避免重複或破壞現有表：

- player_profiles：player_id、name_key、unit、display_name、base_avatar_id、season、exp、revision、最後簽到日期、legacy_imported_at。
- player_credentials：player_id、PIN 雜湊、失敗次數、locked_until。私有 schema，不能由瀏覽器讀寫。
- player_sessions：session token hash、player_id、到期、撤銷、active_connection_id。
- player_items：instance_id、player_id、catalog_id、category、durability、equipped_slot、provenance、revision。每件實體獨立 ID，服裝與武器一起納入容量檢查。
- player_effects：護盾、輕傷、重傷、抓人、冷卻的截止時間及事件來源；不保存每幀動畫。
- game_events：event_id、kind、actor、target、server_time、結算結果，用於去重、扣點與追蹤。
- rma_tasks：task_id、room_id、target_id、claimer、狀態與截止時間。
- gacha_requests：request_id、player_id、材料 ID、抽獎結果、pending / committed / cancelled 與期限。
- world_drops：drop_id、來源、catalog_id、位置、claimed_by 與結算狀態，防止兩人各撿一份。

原子交易由受控後端函式完成。前端不能直接 UPDATE EXP、資產或憑證。私有表不暴露 Data API；需對外資料採最小權限與資料列層級安全性，不提供全開寫入 policy。經驗 / 耐久 / 服裝數量 / 容量 / 事件唯一性均由資料庫或受控交易強制約束。

### 5.3 即時協調與防作弊範圍

- 房長協調 NPC 路徑、短期動畫與位置快照；切換時使用 room_epoch 排除舊房長封包。
- 前端只提交操作請求；後端產生機率結果與持久化獎懲。有效事件驗證至少包括來源、時間、距離、冷卻、NPC 生命週期與重複 ID。
- 傷害進度與獎勵不能僅依前端聲稱「已擊倒」；需後端保存足夠的戰鬥事件摘要與生命值判定。若未完成此驗證，不能開放新版資產獎勵並宣稱防作弊。
- 仍不保證阻止修改客戶端座標、自動操作或串通房長；完整權威位置模擬不在本版範圍。文件與 UI 不使用「工業級」「完全杜絕作弊」等保證。
- 不將每幀動畫寫入資料庫；NPC 傷害結算、拾取、扭蛋、修裝等離散事件才持久化。
- 掉物轉移須以同筆交易從背包移出、產生共享掉落；撿取由後端競爭取得一次，地點先驗證可達。

## 6. 遷移、重置與斷線

### 6.1 部署順序

先部署後端相容介面與資料結構，再部署前端；最後以 Gather 專用開關啟用 Season 2。不得借用或改動入口網站卡片開關。

- 舊版前端啟用後需升級，不能繼續寫 Season 1 資料。
- 先備份現有可取得資料；瀏覽器本機資料無法由管理者遠端完整備份，首次新版登入先在原瀏覽器留只讀備份副本。
- (player_id, season) 的遷移原子且僅一次：舊賽季 EXP 歸零、重算 Lv.1，保留人物與物品。新帳號也從 0 起。
- 首次本機匯入僅接受現有 catalog、合法耐久、容量與服裝數量；超額舊物保留為不可參與交易的遷移待領區，領取時檢查容量，不能靜默刪除。
- 本機歷史資產只能匯入一次。不同裝置各自有舊背包時不自動合併，須選主要裝置或交管理者處理，避免複製。
- 雲端已 Season 2 時禁止再匯入舊 EXP / 道具；本機只讀備份不作遊戲權威。

### 6.2 每日簽到

由後端以 Asia/Taipei 日期判定，讀取日期、加 50、寫日期在同筆交易；跨分頁請求只發一次。重置當天標記已處理且不發獎，下一天起適用。

### 6.3 保存與斷線

- 資產事件即時保存，不等點重新整理才保存；revision 防止舊快照覆蓋。
- 重新整理等待未完成交易，8 秒後提供重試或取消重整，不無限轉圈；不能假裝保存成功。
- 背景切換的短暫連線中斷先顯示淡色「重新連線中」，持續失敗才顯示紅字；暫停新交易，保留 pending request_id。
- 重連先取後端快照，再按 request_id 查詢未確定交易；已成功就套用一次，未成功可重試。禁止整份上傳過期本機存檔。
- 無後端時可看場景與聊天的既有可用模式，但不允許離線抽獎、獎懲結算或資產交易；不累積可反灌雲端的離線 EXP。
- 伺服器時間決定截止；失敗不能用切換手機 App 或刷新跳過重傷 / 罰則。

## 7. 模組邊界與實作順序

以下路徑是計畫目標；先確認最新 repo，若同責任模組已存在則擴充，不建立第二套相同功能。

- combat.js / hunt.js：NPC 受擊、三擊制、抓人與護盾結果；實際檔案依 repo 核對。
